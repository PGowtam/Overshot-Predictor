# Regression Head Underfitting Analysis

## Overview
During the live execution simulation, the dual-threshold backtester failed to take any trades. Upon investigation, it was discovered that the regression head (`Pred_OS`) was severely underfitting the dataset. While the true overshoot magnitudes in the data reach up to 16 bricks, the model's maximum prediction was mathematically capped at `0.80`.

This document outlines the statistical distributions, the architectural reasons for this failure, and why regression on tick-level financial data often results in "mean-hugging" behavior.

---

## 1. True Label Distributions
To understand the problem, we first analyzed the true execution labels (`y_mag`) generated by the `sim_label_generator_mp.py` engine.

### Training Set (2020 - 2025)
* **Total Samples:** 49,408
* **Win Rate (`y_class = 1`):** 36.28%
* **Loss Rate (`y_class = 0`):** 63.72%

**Overshoot Magnitude (`y_mag`) Stats:**

* **90th Percentile:** 2.3305

### Test Set (2026 Out-of-Sample)

**Overshoot Magnitude (`y_mag`) Stats:**

> [!NOTE]
> The labels are perfectly healthy. Roughly 10% of all trades in both the train and test sets achieve an overshoot magnitude greater than 2.0.

## 2. The Model Architecture

The neural network utilizes a dual-head architecture branching from a shared LSTM representation:
```python
# Shared Representation
lstm_out = LSTM(32, return_sequences=False)(fused_inputs)
lstm_out = Dropout(0.3)(lstm_out)

# Head 1: Classification (Will it hit TP before SL?)
prob_win = Dense(1, activation='sigmoid', name='prob_win')(lstm_out)

# Head 2: Regression (How many bricks will it overshoot?)
pred_os = Dense(1, activation='relu', name='pred_os')(lstm_out)
```

### Loss Functions
* **Classification:** `BinaryCrossentropy`
* **Regression:** `Huber(delta=1.0)` (Weighted at 0.3 relative to the classification head)

---

## 3. The Prediction Failure

Despite 10% of the true data exceeding `2.0`, the model's predictions on the 2026 Test Set were:
* **Min Prediction:** 0.0000
* **Max Prediction:** 0.8084
* **Mean Prediction:** 0.6975

The model literally never predicted a value $\geq 1.0$. Because the live simulator required a prediction of $\geq 2.0$ to open a trade, the circuit condition was physically impossible to meet, resulting in 0 trades.

---

## 4. Why Did the Model Underfit?

The model's failure to predict extreme values is a classic symptom of **Variance Minimization (Mean-Hugging)** in noisy datasets. 

### A. The Signal-to-Noise Ratio
Tick-level financial data is dominated by random walk mechanics (noise). Predicting the *exact magnitude* of a trade's peak excursion relies on factors occurring long after the trade is opened. The model struggles to find a deterministic feature in the `(10, 100, 9)` order book snapshot that guarantees a massive 3.0+ brick overshoot. 

### B. Loss Function Economics
Because 64% of the dataset consists of losing trades (where the magnitude is mathematically bounded $< 1.0$), the dataset is heavily skewed towards small numbers. 

If the model "sticks its neck out" and predicts a `3.0` for a specific trade, but the trade actually reverses instantly resulting in a `0.2` loss, the model is hit with a massive error penalty by the Huber Loss function.

**The mathematically optimal strategy for the neural network is to cheat:**
Instead of trying to predict the exact magnitude, the model learns to output a highly conservative number near the global median/mean (around `0.70 - 0.80`) for almost *every single trade*. By predicting `0.75` across the board, the model guarantees that its error variance is always small, effectively minimizing the Huber loss without actually learning anything about extreme momentum.

### C. The ReLU Activation
The `ReLU` activation allows unbounded positive outputs, but without strong, consistent feature correlations driving the weights upward, the network's weight updates naturally decay toward a safe center of gravity.

## 5. Conclusion & Resolution

Predicting *direction* (Classification) is fundamentally easier than predicting *magnitude* (Regression) in financial markets. 

To resolve the 0-trade issue:
1. We must recognize that the regression head is not a reliable filter for execution because it has collapsed into a mean-predictor.
2. We disable the `Pred_OS_threshold` (setting it to `0.0`).
3. We rely entirely on the classification head (`prob_win >= 0.55`) to filter high-probability entries, allowing the strict 1:1 SL/TP logic of the execution engine to handle the actual risk-reward mechanics.
